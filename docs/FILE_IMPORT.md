# V1.9.2 本机文件导入、校对与当前草稿分析

默认只提取文件文字并提供人工校对草稿；可选模型整理，再人工校对 JSON 和本地结构复验。完整草稿经另一次明确确认后，可同页本机分析，不调用模型、不保存或提升验证标记。提取、整理与校验均不自动分析。先用纯虚构或手工脱敏文件；无身份验证，不用于未经脱敏的真实简历、共享电脑、公网、代理或端口转发。

代码已按职责分类，原启动命令不变；当前实现和测试位置见 [代码目录与开发导航](PROJECT_STRUCTURE.md)。下方分版本验收保留当时的测试统计。

## 安装和运行

在项目根目录 PowerShell 运行，无需 `.env`、模型密钥或原演示服务：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -X utf8 file_import_server.py --port 8002
```

保持终端开启，浏览器打开 `http://127.0.0.1:8002/import`：

1. 点击“选择文件”，选择仓库的 [`examples/file_import_synthetic.txt`](../examples/file_import_synthetic.txt)。所有项目与岗位均为虚构。
2. 点击“提取并预览文字”，预期显示 5 行原提取文字和对应的修正框。选择文件本身不会自动传输。
3. 编辑修正框，点击“确认本页文字校对”。只显示“已确认本页文字校对（未保存）”，声明仍待核实，没有匹配结果。
4. 点击“取消并清空”删除本页草稿，或选择另一文件重新提取。结束时在终端按 `Ctrl+C` 并关闭页面。

默认端口 8002 与原分析页 8001 分开。占用时改为 `--port 8003`，打开相同端口的 `/import`；不要关闭未知服务。原 `/private` 启动命令及 JSON 边界不变。

## 可选：用修改后的文字整理 JSON

仅使用上述默认命令时，模型整理关闭，文件提取仍不需要密钥。需要模型整理时，在本地 `.env` 或环境变量配置已有的 `DASHSCOPE_API_KEY`；不要覆盖现有 `.env`、把密钥填入页面或提交到仓库。`.env` 已被 Git 忽略。密钥、网络和模型兼容性以实际服务结果为准。

在运行该服务的终端按 `Ctrl+C` 停止旧进程，再运行并刷新页面：

```powershell
.venv\Scripts\python.exe -X utf8 file_import_server.py --port 8002 --enable-model-format
```

开启服务不会自动发请求。操作顺序：

1. 选择虚构／脱敏文件，点击提取，修改文本框中的文字。
2. 在“是否整理为 JSON？”选择“用千问整理成 JSON”。指定当前文字是候选人资料、JD，还是两者都有；仓库的虚构 TXT 同时包含两者，可选“两者”。
3. 如果只有简历，可在“补充另一半”粘贴已脱敏的 JD；只有 JD 时可补充候选人资料。也可以留空，缺少部分保持 `null`，不能当作完整分析输入。
4. 确认资料来源类型，默认是纯虚构资料；真实来源须先手工脱敏并选择对应类型。案例标识使用匿名英文小写／数字／下划线，不填写姓名。
5. 点击“确认本页文字校对”，再勾选外发同意。发送前删除姓名、联系方式、公司／学校及其他不必要信息。勾选和点击生成是一次主动外发操作，会发送当前修正框及补充框文字到外部千问服务，并可能产生 API 费用；原文件及原文件名不发送。
6. 点击“用已修改的文字生成 JSON 草稿”。结果可以继续修改，然后点击“仅校验当前 JSON（不调用模型）”。修改校对文字、补充文字或设置会撤销旧结果和外发同意，必须重新校对并同意。
7. JSON 使用加高等宽编辑区，可拖动右下角纵向调整；上方分别列出岗位 JD 和候选人资料是否缺少。修改 JSON 后旧缺项结论失效，须重新校验；校验失败时保留可修改的草稿，但不沿用旧的通过结论。
8. 本页成功生成过后，再次点击生成先显示“可能再次产生 API 费用、替换当前草稿”的提醒；明确点击“确认再次生成”才发送，取消保留草稿。修改文字或设置不会绕过这次提醒。刷新、清空或更换文件后不保留历史提醒状态；首次调用仍可能收费，失败／超时后也可能已经产生用量。仅校验 JSON 不调用模型。

输出使用[原私有案例字段约定](PRIVATE_CASES.md)：`case_id`、`data_kind`、`notice`、`job`、`candidate`、`qualifications`。匿名岗位／候选人／要求／证据 ID 由 Python 生成；能力证据固定 `verified=false`，资格固定 `verification=unverified`，没有 `expected`、匹配状态或 `trusted_facts`。

只有简历时 `job=null`；只有 JD 时 `candidate=null`，显示缺少部分。两者齐全且结构合法才显示“JSON 结构通过”，不代表技能归类、层级、优先级、声明或招聘资格真实。模型整理时检查描述是否逐字出现在对应角色的校对文字中；这个检查不能证明语义映射正确，也不保证没有遗漏。用户编辑 JSON 后的本地校验仅检查字段、安全格式和验证标记，不重新核对引用。

本页不自动复制、下载、保存或分析。完整草稿可以按下节在本页明确确认分析，无须另存文件。原 `/private` 不会自动读取新草稿，启动快照和原 JSON 数据均不改变；若另存草稿，只能手动保存到被忽略的 `notes/`，不要覆盖已有文件。

已完成离线回归及一次纯虚构文字的真实千问格式化联调，未做真实资料准确性验收。一次成功只证明当次环境和输入可运行；后续调用仍可能因模型可用性、参数支持、网络或密钥失败。错误不展示为成功，费用以平台用量／账单为准，页面 Token 数可能未返回。

## 使用当前草稿进行本机分析

1. 按上节生成草稿并人工修正 JSON；岗位 `job` 和候选人 `candidate` 都必须完整提供，不能为 `null`。
2. 点击“仅校验当前 JSON（不调用模型）”。生成成功本身不会开启分析，须重新校验当前草稿；校验失败保留编辑内容，但撤销旧分析许可。
3. 逐项复核后勾选“我已逐项复核当前 JSON，确认用它分析”，再点击“确认并分析当前草稿（本机，不调用模型）”。这不是外发同意，分析不产生模型费用。
4. 同页查看每项岗位要求、关联证据和来源、规则状态、`trusted_facts`（可信事实）、未关联证据与独立资格声明。完整流程不需要保存草稿或重启服务。
5. 分析期间“生成 JSON”和“仅校验”暂时禁用，成功、失败、超时或撤销后恢复。前序提示只说明文字校对或 JSON 校验步骤，不否认后续已完成的分析。
6. 修改 JSON 后结果立即隐藏，确认被撤销；重新校验并确认再分析。修改校对正文或整理设置会同时清除旧 JSON。刷新、换文件或清空不保留草稿或结果。
7. 在结果的“筛选要求卡片”中选择“全部要求／待核实／缺少证据”。上方四态计数始终统计全量，另行显示全量和当前显示项数；零项有明确提示，不表示程序失败。只隐藏要求卡片，不重新请求或改变判定、可信事实、其他证据和资格声明。新分析、编辑、撤销或清空均重置筛选；新报告从全部要求开始。

`POST /imports/analyses` 只接受 `draft` 与精确布尔值 `analysis_confirmed=true`。草稿严格为前述六字段，服务器重新校验，再复用 `analyse_private_case` 分析同一份内存输入；不接受文件路径、模型、输出位置、`expected` 或已核实证据。JSON 请求重复键、非有限数、大小／深度限额及本机同源约束与原校验一致。接口不依赖模型开关或密钥，但页面中的生成步骤仍须启用模型整理；本版没有独立粘贴／上传 JSON 的新入口。

分析响应为 `report`、`analysis_performed=true`、`saved=false`；报告标记 `execution_status=completed`、`analysis_mode=offline_deterministic`、`model_generated=false`。页面核对报告的输入、要求、关联 ID、状态和全部事实；错位或篡改不能展示为完成。此草稿没有人工预设，`verification.applicable=false`，不会声称“案例核对通过”。

导入证据全部 `verified=false`：相同技能 ID 的声明为 `unverified`（待核实），没有相同技能 ID 的证据为 `missing`（缺少证据）。页面保留四态计数，但 `matched`／`partial` 必须为 0。这是输入边界，不是程序失败，也不证明现实中不会。学历及届别仅单独显示声明，不参与技能匹配或录用决策。

传输超时返回固定 408，缺项返回固定 `incomplete`／422，执行异常返回固定 `analysis`／503，不回显原文、异常或路径。浏览器等待覆盖响应正文最多 15 秒，编辑、撤销或清空后的晚响应不能恢复旧结果；失败后可以主动重试，不会触发模型。停止页面等待不保证服务端立即停止，但分析只处理有上限的当前内存草稿，不做文件写入。

## 校对定位与操作引导

- 顶部显示当前步骤和下一动作，解释生成、校验与分析的前置条件及暂时禁用原因。服务未启用模型整理、尚未确认文字或未勾选外发同意时分别提示；分析确认不能代替外发同意。引导不会自动发请求、保存或替用户确认。
- JSON 草稿的字段错误可附最多 8 项定位，例如 `job.requirements[1].priority`，表示第 2 项要求的优先级字段；数组下标从 0 开始。仅返回约定字段、受限下标和固定原因，不回显输入值、未知字段名、原始异常或模型文字。
- 点击错误项旁的“定位”按钮，编辑区获得焦点、选中对应原始值并显示行列；缺失字段则选中最近存在的父级并明确提示。不会补写字段、格式化草稿、自动校验或新增模型请求，仍需自己修正后重新校验。使用原始文本偏移区分同名字段与转义键名；修改后旧按钮失效。语法、重复键、非有限数或超过定位限制时保守拒绝，不猜测位置。定位索引限 120000 个 JavaScript UTF-16 单元、32 层；可能比服务端字符限制更保守，但不改变原校验标准。
- 定位是原严格校验失败后的有限解释，不参与是否通过的决定，也不穷尽全部错误。修正后必须重新完整校验。隐私命中不返回字段定位；语法、重复键、非有限数等原始 JSON 解析错误仍使用通用提示。
- `POST /imports/validate-json` 或 `/imports/analyses` 的 `error_code=json` 响应可附 `field_errors`，每项仅有 `path`、`reason`；成功响应不变。页面再次核对路径和原因白名单，未知、额外、过量或状态不符的提示不会显示；仍不展示服务端 `detail`。
- 修改或清空后旧字段定位失效，晚响应不能恢复旧错误。证据层级显示学习、练习、项目、生产实践并保留原始标识；要求显示必需／加分和输入优先级原值，不推断数值含义、不增加评分或改变技能四态。

## 支持范围

| 格式 | 提取范围与位置 | 重要限制 |
|---|---|---|
| UTF-8 TXT | 解码后的行顺序，中间空行保留 | 可含 UTF-8 BOM；拒绝其他编码、二进制和危险控制字符；行分隔符不显示在框内 |
| 文字型 PDF | 每页文字、页码及空白页位置 | 不识别图片或扫描件；排版顺序可能不准确；加密文件拒绝 |
| Word DOCX | 正文普通段落和表格、正文块及单元格位置 | 合并单元格不重复；不是 Word 页码；图片、文本框、页眉页脚、脚注和修订等可能遗漏 |

旧式 `.doc`、宏文档 `.docm` 不支持。DOC 需用 Word“另存为”DOCX，不能仅修改后缀。结果不代表原简历全部栏目，必须对照原件检查遗漏和顺序。人工修正不改写原提取文本，也不获得真实性证明。

## 数据与安全边界

- 文件字节只发送到 `127.0.0.1`，不发送原文件名或本机路径；服务器不接收路径读取文件。浏览器的选择控件仍会在本机显示文件名。
- 不保存原件、提取文字或校对／JSON 草稿，不生成文件、不使用浏览器持久存储。刷新、清空或关闭会丢失草稿。“确认校对”不外发，只有主动模型整理才发送修正文字。
- 默认提取、本地 JSON 校验和确认后的草稿分析不调用模型；只有模型整理需要启动开关和外发同意。没有 RAG、OCR、数据库或云端文件解析。文档指令只作为文字，不执行宏或命令，不跟随链接；含宏组件或嵌入对象的 DOCX 拒绝。
- 工作进程只接收字节；固定错误及日志不回显原文、原文件名、密码或路径。HTML 使用安全文字节点展示。
- 提取成功只表示返回文字；模型整理成功只表示返回待复核 JSON。提取／整理／校验均固定 `verification=unverified`、`analysis_performed=false`、`saved=false`。只有另一次明确确认的分析生成规则匹配和 `trusted_facts`，不生成资格结论或升级验证标记。
- 模型整理前扫描常见联系方式、密钥、路径等格式，命中则不发送；有限扫描不保证发现所有隐私。原分析入口没有自动连接，来源位置属于校对片段，不能证明人工修改后的内容来自原件。
- 服务限制本机、同源、Host、代理标记、固定请求头和查询参数，响应 `no-store`。这些不是认证，同机其他进程仍可能访问。

## 限制、错误和恢复

- 文件最多 2 MiB；PDF 最多 20 页；最多 2000 个片段、100000 个 Unicode 字符。超限整份拒绝，不静默截断。
- DOCX 最多 256 个 ZIP 条目、声明解压总量 8 MiB、单条压缩比 200 倍；重复条目或嵌套深度超限拒绝。
- 读取上传最多 15 秒，单独解析进程最多 10 秒。超时只终止本次创建的解析进程，不查找或终止其他服务。
- 解析进程设置 512 MiB 内存限制，设置失败即拒绝。Windows 使用 Job Object，其他支持的环境使用资源限制；当前运行证据来自 Windows。
- 每个服务实例同时只处理一次文件导入或模型整理，忙碌返回 503；不调用模型的 JSON 校验与内存草稿分析不占用该锁。页面阻止分析期间重复分析、校验或生成，服务端仍可处理其他本机请求；这不是身份验证或完整限流。工作进程及限额不是完整的恶意文件安全沙箱，不用于不可信互联网附件。
- 浏览器等待最多 30 秒，覆盖正文读取；取消或换文件后旧响应不能覆盖新预览。取消页面等待不保证服务端立即终止，其解析仍受独立时限约束。
- JSON 请求最多 256 KiB、120000 个字符和 32 层嵌套；编辑后的 JSON 原样交给服务端严格校验，拒绝重复键与非有限数，不静默覆盖或改写字段。外发的校对正文与补充文字合计最多 12000 个字符，最多 40 项岗位要求、60 条能力证据、10 条资格。
- 模型使用项目固定千问模型与地址，客户端不能指定模型、路径或输出位置；不开放工具。SDK 配置 20 秒网络超时、0 次自动重试、4096 个输出 Token 上限并关闭思考模式，与既有调用参数保持一致；这些配置未证明远程兼容性，也不是总耗时或费用的硬保证。
- 模型／JSON 校验的浏览器等待最多 45 秒；正文修改或清空后晚响应不能恢复旧 JSON。取消等待不能撤销已经外发的请求或费用，先核对平台用量再决定重试。
- 格式化／JSON 校验错误只返回固定 `error_code` 和固定说明：`privacy` 为有限隐私格式命中；`input` 为请求字段或 JSON 请求解析错误；`json` 为草稿字段、类型或验证标记错误；`quote` 为模型摘录不在对应角色的校对文字中；`output` 为模型输出字段或结构不合约定；`model`／`timeout` 为模型不可用／超时。页面只使用类别白名单，不回显服务端 `detail`、输入或异常；未知类别和一般 HTTP 拒绝使用固定降级提示。分类不代表完整隐私或语义检测，手动编辑 JSON 后的校验不会重新核对引用。
- 413：大小或提取量超限；415：格式不支持；422：解析、文字层、编码或字符异常；408：传输或解析超时；503：忙碌或资源不可用。页面不显示服务端原始异常，处理后可重试。
